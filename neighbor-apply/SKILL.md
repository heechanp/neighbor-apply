# neighbor-apply: 주제 검색으로 서로이웃 신청하기

사용자와는 **항상 한국어로** 대화한다.

먼저 `references/settings.md`(계정, 그룹, 모드, 인원, 간격)와 `references/message.md`(신청 메시지 쓰는 법)를 읽는다. **메시지는 message.md가 기준이다.**

이 스킬은 **PC에서만** 된다(신청에 로그인된 Aside가 필요하다). 클라우드나 휴대폰 채팅에서는 "PC에서 '경제로 서이추 해줘'라고 하면 할게요"라고 안내한다.

작업 폴더는 항상 `C:/Users/gmlck/claude/neighbor-apply/서이추작업/<계정>_<YYYY-MM-DD_HHMM>/`이다(신청 기록을 여기서 모아 보므로 다른 곳에 만들지 않는다. 깃헙에는 안 올라간다). 아래 `<스킬>`은 이 SKILL.md가 있는 폴더다.

## 0단계: 계정·검색어 정하기

- 계정: 사용자가 말한 계정(지솜/모멍찌), 말이 없으면 settings.md의 기본 계정.
- 검색어: 사용자가 말한 주제. 없으면 settings.md에 적힌 그 계정의 기본 검색어 중 하나를 고르고 무엇으로 했는지 한 줄로 알린다. 검색어를 여러 개 주면 인원을 나눠 모은다.
- 인원: 사용자가 말한 수, 없으면 settings.md 기본값. **하루 100명 제한**이 있으니 100을 넘으면 100으로 줄이고 알린다.

## 1단계: 검색해서 사람 모으기 (로그인 없이 공개 정보)

```
python <스킬>/scripts/search_posts.py --account qlgovl_ --keyword "경제" --count 30 --out "C:/Users/gmlck/claude/neighbor-apply/서이추작업/qlgovl__<날짜시간>"
```
- 네이버 블로그 글 검색(기본 최신순)을 쪽마다 넘기며, 블로그 주소 기준으로 **한 사람당 글 하나**만 고른다.
- 건너뛰는 사람: 내 계정들, **예전에 이 계정으로 신청했거나 이미 이웃이었던 사람**(서이추작업 아래 이전 폴더들의 `apply_done.json`을 모아 본다), 이름이 업체·홍보 같은 블로그(settings.md에서 끌 수 있음), 본문이 거의 없는 글.
- 사람마다 글 본문 **앞 500자 + 끝 300자**를 담는다.
- 결과 `candidates.json`: `{nick, blogId, blogName, logNo, title, date, text, flags}`. 메시지 쓰기용으로 30명씩 `cand_part1.json`… 으로도 나눠 둔다.

## 2단계: 신청 메시지 쓰기 → plan.json

**누가 쓰나:** Agent 도구가 있으면 `model: "sonnet"` 서브에이전트에게 **`cand_partN.json` 하나당 하나씩** 맡긴다. 프롬프트에 이 단계, `references/message.md` 경로, 계정 소개(settings.md의 그 계정 줄), 맡은 파일 경로, 저장 경로(`plan_partN.json`), 아래 형식을 적고 **글만 쓰게 한다**(Aside 실행·신청 금지). 파트마다 "주로 쓸 첫마디 유형"을 message.md의 유형 중에서 다르게 나눠 준다. 결과를 합쳐 내가 message.md 기준으로 훑고, 첫마디·문장 틀이 겹치는 것만 고친다. Agent 도구가 없으면 내가 직접 쓴다.

`<작업폴더>/plan.json`:
```
{"myId": "qlgovl_", "myNick": "지솜", "group": "새 그룹",
 "items": [{"blogId": "...", "nick": "닉네임", "title": "글 제목", "message": "신청 메시지"}]}
```
- 메시지가 맞지 않는 사람(message.md '이럴 땐 빼기')은 items에 넣지 않고 `"skipped": [{"blogId", "nick", "why"}]`에 적는다.

## 3단계: 보여 주기 또는 바로 신청 (settings.md의 모드)

- **확인 모드**: 표(닉네임 · 글 제목 → 메시지)와 뺀 사람(이유 한마디)을 보여 준다. 사용자가 고치라면 고치고, "신청해줘"라고 하면 4단계.
- **바로 모드**: 표 없이 4단계로 가고, 끝난 뒤 결과만 보여 준다.

## 4단계: 네이버에 신청하기 (PC의 Aside)

```
python <스킬>/scripts/make_apply_scripts.py "<작업폴더>/plan.json"
powershell -NoProfile -ExecutionPolicy Bypass -File "<작업폴더>/apply_fill.ps1"
```
- 처음 쓰거나 엔진을 고친 뒤에는 `--dry`로 먼저 돌려 본다(신청 화면을 다 채우고 '확인'만 안 누름, 결과 `status: dry`).
- 30명이면 10분쯤 걸리니 **백그라운드로 실행**하고 끝나면 알린다.
- 맨 처음 **Aside에 로그인된 계정이 plan의 myId와 같은지** 확인한다. 다르면 아무것도 안 하고 `ACCOUNT_MISMATCH`로 끝난다(종료 코드 3) → "Aside 브라우저에서 ○○ 계정으로 바꿔 로그인해 주세요. 다 되면 '이어서 신청해줘' 하시면 돼요"라고 알린다.
- 사람마다 `m.blog.naver.com/BuddyAddForm.naver?blogId=…`를 열어 **서로이웃 선택 → 그룹 선택 → 메시지 넣기 → 확인**. 넣은 메시지가 그대로 들어갔는지 확인한 뒤에만 확인을 누른다.
- 건너뜀(신청 안 함, 다음에도 다시 안 봄): 이미 이웃·신청 중, 서로이웃을 안 받는 블로그(서로이웃 선택이 막힘), 나 자신.
- 한 명 신청할 때마다 settings.md 간격(무작위)만큼 쉰다.
- **하루 신청 제한·자동입력 방지**가 뜨면 그 자리에서 전체를 멈춘다(`LIMIT STOP`, 종료 코드 2). "네이버 서이추 제한에 걸려서 ○명 신청하고 멈췄어요. 내일 '이어서 신청해줘' 하시면 남은 ○명 신청할게요"라고 알린다. 스스로 다시 시도하지 않는다.
- **"이어서 신청해줘"**: 같은 작업 폴더의 apply_fill.ps1을 다시 실행한다. 이미 처리한 사람은 `apply_done.json`으로 건너뛴다.
- 끝나면 `apply_log.txt`의 `RESULT` 줄들에서 성공 수, 건너뜀(이유별 수), 실패를 알린다. 신청 뒤 네이버가 띄운 알림 문구는 `msg`에 남는다. **처음 몇 번은 알림 문구를 같이 보여 주고**, 성공·제한 판정이 맞는지 확인해 engine_apply.js의 정규식(`OK_RE`, `LIMIT_RE`, `ALREADY_RE`)을 고친다.

## 사용자가 메시지나 설정을 고쳐 달라고 할 때

- 메시지는 `references/message.md`의 "사용자 피드백 기록"에 날짜와 한 줄을 추가한다.
- 계정·그룹·모드·인원·간격은 `references/settings.md`만 고친다.
- 고친 뒤 CLAUDE.md의 규칙대로 `save_skill.py neighbor-apply "바꾼 내용"`으로 올린다.

## 하지 않는 것

- 하루 100명 넘게 신청하기, 제한이 떴는데 다시 시도하기
- 이웃 삭제, 신청 취소, 받은 신청 수락·거절
- 메시지에 링크·홍보·광고 문구 넣기, 글에 없는 내용 지어내기
- 한 번 실행에서 같은 사람에게 두 번 신청하기
